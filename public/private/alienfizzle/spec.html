§ 01 · 视角与世界观

从俯视到一点透视
从飞机到守线人

1.1 视角

  • 必须一点透视斜俯视: 摄像机俯角 30-40°, 远端通道收窄, 形成纵深感
  • 必须仍为 2D 渲染: 不引入 3D 引擎, 用 2D 透视技巧(梯形通道 + 远小近大缩放) 实现伪 3D
  • 建议保留竞品参考的卡通白模质感, 不追求拟真写实
  • 可选背景层可加视差滚动(parallax) 增强纵深, 不强制

1.2 题材与节奏转换

维度v2 飞机大战v3 人物守线
玩家角色飞机, 屏幕底部向上推进主角 + BOBO, 站定底部防线
敌人动线从顶部冲下从顶部推进, 直到防线前停下攻击
节奏类型推进式 shooter (前进 = 主旋律)endless wave 塔防 (守 = 主旋律)
失败条件飞机被击落防线持久度归零
核心张力"打得快 vs 躲得过""贪宝箱 vs 守防线"双轨决策
设计意图: 题材从"主动进攻"换成"被动守线", 让 endless 节奏自然成立 — 玩家不再有"打到尽头"的预期, 而是"撑多久"的存活叙事, 更契合 A 路单机休闲爆款的 30-60s 单局节奏。
§ 02 · 角色系统

主角 + BOBO + 外星生物
三方关系定义

2.1 主角

属性规格
形象人物(具体设计待美术 brief), 站姿守线
站位屏幕底部防线上方约 1 个角色身位
操作左右自由滑动(鼠标拖动 / 触屏滑动), 不离开防线高度
开火自动垂直向上射击, 不受玩家操作影响
武器覆盖式 — 拿到新武器立即替换旧武器, 不叠加
武器作用范围仅影响主角自身弹道, 不影响 BOBO
初始武器基础单发直射(数值待定)

2.2 BOBO (悬浮球辅助机器人)

属性规格
形象小型悬浮球体, 科技感, 跟主角风格统一
站位默认贴身主角右侧约 0.5 个身位, 与主角同步横移
开火自动垂直向上射击, 独立弹道
属性来源仅由右通道状态门修正, 不受宝箱武器影响
初始属性攻击力 / 攻速 / 弹道数 / 弹道速度 / 暴击率 = 基础值 (待数值表)
命名来源BOBO(诺) — 单音节, 与 Nova/Nimbus 同字母系, 国际化通用

2.3 镜像 BOBO

  • 必须获取条件: 击破宝箱通道里的 镜像武器 (特殊宝箱掉落)
  • 必须初始位置: 主角左侧 0.5 身位, 与原 BOBO 对称
  • 必须属性完全继承: 当前属性 + 后续所有状态门变化 同步镜像
  • 必须独立弹道: 镜像后总火力 = 主角 1 + BOBO 1 + 镜像 BOBO 1 = 三弹道
  • 必须主角横移时, 两个 BOBO 同步横移, 保持对称
  • 待定是否允许多次镜像(2→4→8 个 BOBO)? 初版限制最多 2 个, 后续视平衡性调整

2.4 外星生物 (敌人)

  • 必须从屏幕顶部出现, 仅在右通道(接敌通道)推进, 不进入左通道
  • 必须推进速度 慢于状态门(状态门会从敌人之间穿过到达主角)
  • 必须到达防线前 停下并攻击防线, 持续消耗防线持久度
  • 必须被击杀后立即消失, 不掉落物品
  • 建议分 3 档: 小兵 / 精英 / Boss, 推进速度与血量递增, 视觉差异明显
  • 可选外星生物形态: 软体 / 机甲 / 触手, 美术自由发挥, 保持卡通可识别
§ 03 · 战场布局

双通道 2 : 3 空间几何

这是 v3 改造的物理基础。所有后续机制(状态门躲避 / 主角横移 / 子弹方向)都建立在这套空间几何上。

3.1 通道比例与单位换算

设屏幕宽度 = 5 个单位(后简称 U), 则:

  • 左通道(宝箱通道): 宽 2U, 占屏幕 40%
  • 右通道(接敌通道): 宽 3U, 占屏幕 60%
  • 主角 hitbox 宽度: 0.5U (含 BOBO 贴身, 实际有效宽度需考虑 BOBO 边缘)
  • BOBO 单体宽度: 0.3U
  • 状态门固定宽度: 接敌通道一半 = 1.5U
  • 防线高度: 屏幕底部约 1U 高的横向带
图 3-1 · 战场布局示意 · 一点透视双通道 2:3 + 主角 BOBO + 状态门居中场景

3.2 主角横移规则

规则说明
横移范围整个屏幕宽 5U 自由滑动, 含宝箱通道和接敌通道
纵向限制仅横轴移动, 不离开防线高度(主角守线职责)
BOBO 跟随所有 BOBO 与主角 刚性绑定同步横移
边界判定主角边缘碰到屏幕左右边时停下, 不会出屏
滑动手感1:1 跟手, 无加速度曲线, 无延迟(休闲游戏快反馈优先)

3.3 子弹方向规则

  • 必须主角和所有 BOBO 的子弹 始终垂直向上发射, 无论主角在哪个通道
  • 必须子弹位置由发射者当前 X 坐标决定 — 主角在宝箱通道 = 子弹打宝箱通道
  • 必须子弹不能跨通道(物理一致性)
临界情况 · 不抢行修正: 主角恰好骑在两通道分界线上时, 会出现 主角弹道在宝箱通道 + BOBO 弹道在接敌通道 的分裂状态。这是 feature 不是 bug, 代码不要做任何对齐 / 吸附 / 偏移修正, 让玩家自由利用这个边界位置做"边贪宝箱边守接敌"的精妙操作。
§ 04 · 宝箱通道(左)

冻结卡位 · 主角武器仓库

4.1 宝箱机制

  • 必须宝箱在通道内 冻结不动, 不自动下滑
  • 必须宝箱有血量, 被子弹击中累计伤害, 击破后 掉落武器 飞向主角
  • 必须主角击破宝箱后 立即装备武器, 替换当前主角武器(覆盖式)
  • 必须宝箱通道内同时混入 障碍, 障碍击破不掉落任何东西 — 是纯粹的"挡子弹"消耗
  • 建议宝箱与障碍的视觉差异要明显, 颜色 / 形状 / 边框三层区分

4.2 武器分级

等级击破难度武器档次预期出现频率
基础低血量(2-3 颗子弹)普通武器(单发增强 / 散射 / 穿透...)高 60%
精良中血量(5-8 颗子弹)精良武器(范围 / 弹反 / 追踪...)中 30%
稀有高血量(15-25 颗子弹)稀有武器(含 镜像 BOBO 等特殊武器)低 10%

4.3 特殊武器: 镜像 BOBO

  • 必须归类为 稀有宝箱(高血量, 低频出现)
  • 必须装备瞬间在主角左侧 0.5U 位置 生成镜像 BOBO
  • 必须镜像 BOBO 的初始属性 完全继承当前原 BOBO 的所有属性
  • 必须后续状态门变化 同步作用于两个 BOBO
  • 待定已有镜像 BOBO 时再拿到镜像武器, 行为为何? 候选: A 无效化 / B 镜像出第 3 个 BOBO / C 替换并退回某资源 → 初版选 A 无效化

4.4 通道无防御警告

主角离开接敌通道(完全进入宝箱通道)时, 接敌通道的防线段进入 警告状态:

  • 必须接敌通道下方的防线段 红色闪烁(频率约 2Hz)
  • 必须闪烁直到主角任何部分回到接敌通道为止
  • 建议配合短促警告音效(可选, 关闭也不影响游戏性)
  • 可选主角骑分界线时, 闪烁强度减半(部分覆盖)
设计张力: 主角去左通道贪宝箱时, 右通道弹道空缺, 敌人推进无人拦截。警告反馈 = 心理压迫源, 让"贪 vs 守"成为玩家每秒都要重新计算的决策。
§ 05 · 接敌通道(右) · 状态门核心机制

修正即翻转
状态门的状态机

这是 v3 改造的灵魂机制 — 所有减益最终能通过射击修正到 0 并翻转为增益, 上限永远是 buff。把"被动遭遇 debuff"变成"主动消减 + 充能 buff"的双向操作。

5.1 状态门基础规格

属性规格
出现位置接敌通道顶部, X 坐标 随机(0 到接敌通道宽减去 1.5U 之间)
固定宽度1.5U (接敌通道一半), 始终不变, 不随数值缩放
移动方向从顶部向下匀速移动
移动速度显著快于小兵推进速度(约 1.5x - 2x), 保证门会穿过敌人到达主角
同时存在数始终只 1 个, 上一个消失才生成下一个
初始数值随机 buff 或 debuff, 数值范围按数值表(待数值策划)
属性维度攻击力 / 攻击速度 / 弹道数量 / 弹道速度 / 暴击率 / ... (可扩展)

5.2 受击与数值变化

  • 必须子弹击中状态门 消耗子弹(子弹被门吸收, 不穿透)
  • 必须每颗子弹按 固定步进 改变门的数值(步进值在数值表定义, 不同门类型不同)
  • 必须数值变化方向 始终向"增益上限"方向: debuff 减弱 → 0 → 翻转 buff → 充满上限
  • 必须数值实时显示在门上, 颜色随状态变化 — 红(debuff) → 灰(0 中性) → 绿(buff)
  • 必须射击 只改数值, 不改宽度(门的物理尺寸始终 1.5U)

5.3 上限释放阻挡位

  • 必须数值达到 增益上限时, 门 释放阻挡位: 子弹可穿透打后面的敌人
  • 必须释放后门 不消失, 继续向下移动, 保持已达增益上限的状态
  • 必须释放后子弹 不再被消耗(穿透), 数值也不再变化(已达上限)
  • 建议释放后门的视觉变化要明显: 边框由实变虚, 或填充透明度下降

5.4 消失唯一条件

唯一消失条件: 状态门撞到主角, BOBO 吃到当前数值的 buff/debuff, 门 立即消失。
  • 必须"自然流出屏幕底部" 不 算消失 — 它要么撞主角, 要么被主角避开
  • 必须但当门移出屏幕底部时, 实际效果等同于消失(下个门可以生成)
  • 建议视觉上让"自然流走的门"轻微淡出, 区分于"被主角吃掉"的爆开效果

§ 06 · 躲门空间几何

主角与状态门
3 种关系判定

状态门宽 1.5U + 接敌通道宽 3U, 意味着主角在接敌通道内本来就有躲门空间, 不必每次都横跨到宝箱通道。这套几何决定了核心操作手感。

6.1 数值推演

项数值说明
接敌通道宽3U右通道全宽
状态门宽1.5U固定一半
剩余空间1.5U接敌通道内可用于躲门的横向余量
主角 hitbox 宽0.5U含 BOBO 贴身边缘
纯接敌通道躲位1.0U1.5U − 0.5U, 够主角左右两侧各避一半

6.2 三种主角 vs 门的关系

关系 A · 接敌通道内绕门 (主要躲门方式)

  • 门在接敌通道左半 → 主角滑到接敌通道右半
  • 门在接敌通道右半 → 主角滑到接敌通道左半
  • 这是 70%+ 场景的默认躲法, 不消耗"贪宝箱"机会

关系 B · 横跨宝箱通道躲门 (顺便贪)

  • 门在接敌通道正中, 接敌通道两侧躲位都不够宽时
  • 或玩家主动想拣宝箱时
  • 代价: 接敌通道弹道空缺, 防线进入警告状态(§4.4)
  • 收益: 可以击破宝箱拿武器, 子弹打宝箱通道目标

关系 C · 故意撞门 (主动吃 buff/debuff)

  • 门已被打到 S4 上限释放 → 主动撞 → BOBO 吃满 buff
  • 或决定吃当前数值(不等满)时主动撞
  • 或紧急情况下不得不撞(没有更好选择)

6.3 临界场景 · 门居中"针尖挤过"

当状态门位置恰好让接敌通道左右两侧的躲位都 < 主角宽 0.5U 时(理论极端: 门居正中, 两侧各 0.75U), 操作上能挤过去但极险。

设计决策: 保留这个 针尖挤过 的高难操作, 不做碰撞箱宽容判定。这是 endless 类游戏的"操作天花板", 留给硬核玩家炫技。

§ 07 · 防线与失败条件

持久度归零 = Game Over

7.1 防线规格

属性规格
位置屏幕底部, 横跨整个屏幕宽 5U
高度约 1U 高度的横向带
持久度有限 HP, 起始值待数值表(建议 100)

7.2 敌人攻防交互

  • 必须敌人到达防线前 停下, 不继续推进
  • 必须敌人开始 持续攻击, 每秒消耗一定持久度(不同敌人 dps 不同)
  • 必须敌人仍可被子弹击杀, 击杀后立即停止攻击
  • 建议多个敌人同时攻击时, 防线消耗 dps 叠加
  • 可选敌人攻击时有特效(冲撞 / 啃咬 / 射击), 美术自由

7.6.4 分数公式 · 均衡 (D13 拍板)

决策: C 均衡方案, 存活时间 + 防线 HP + 杀敌数 三者都要兼顾, 逼玩家平衡"活久 vs 打多"。

分数 = 存活时间(秒) × 5 + 剩余防线 HP × 2 + 累计杀敌数 × 5
  • 存活时间权重 5: 主导因素, 撑得越久分越高
  • 防线 HP 权重 2: 低权重, 但撑到最后 HP 还很高可以拉分
  • 杀敌数权重 5: 主导因素, 逼玩家主动打怪, 不能只守不打混时间
反 exploit 设计意图: 单一维度主导 (纯存活 / 纯击杀) 会被玩家挖出捷径 (比如只守不打拖时间)。均衡公式使玩家必须兼顾"活久 + 打多", 天然形成策略深度; 且"综合分"比"单一数字"更适合截图分享。

7.6.5 好友榜 · 微信开放数据域 (D13 拍板)

决策: B 方案, 走微信开放数据域 — 免费、微信原生 API, 好友之间对比自己 vs TA 的最高分。

  • 必须无尽模式结算面板显示 好友榜 top 10, 高亮玩家自己的位置
  • 必须破纪录时弹出 荣誉横幅 (独立设计, 金色 + 缩放呼吸动画 + 大事件音), 参考 skill html5-minigame-polish-pipeline 荣誉成就规范
  • 建议结算面板加"分享到微信"按钮 (可选), 用微信原生分享 API, 图片带分数展示
  • 可选陌生人全球榜不做 — 休闲游戏留存意义不大, 且需要自建服务器
技术选型理由: 微信开放数据域是白嫖社交的最佳解 — 0 服务器成本, 用微信关系链好友的比较自然产生比拼欲, 参考《向僵尸开炮》同款架构。集成时多加一个开放数据域子包 (微信文档有现成模板)。
